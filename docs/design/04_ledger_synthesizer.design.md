# LedgerSynthesizer 基本設計書

本設計書は、論点合成モジュールの仕様書（`04_ledger_synthesizer.spec.md`）に規定された反例データの業務論点化、および根本論点優先提示・グルーピングを、全体基本設計書（`system_solution.design.md`）の規約に準拠して**どのように技術的・構造的に実現するか（How）**を定義する。

---

## 1. アーキテクチャと全体設計制約の継承

### 1.1 全体設計制約の適用
- **配置場所**: `specula/src/core/ledger_synthesizer.js`（Pure ESM, Target: ES2022+）。
- **Zero-I/O Core の遵守**: 本モジュールは直接ファイル読み込みや書き込みを行わず、メモリ上で `SolverReport` と形式仕様モデルを受領し、論点カタログ `DomainLedgerCatalog` を合成して返す純粋な変換器として実装する。
- **3アクター分界点の遵守**: LLM を「計算機」ではなく「人間への親切な翻訳・説明インターフェース（Agent）」として配置し、推測による仕様の自己決定を排除する。

### 1.2 逆翻訳パイプライン構成
```
[SolverReport] ──➔ [Dependency Analyzer] ──➔ [Topological Sorter] ──➔ [LLM Domain Translator]

                                                                                     │
```

## 2. 根本論点の優先抽出とグルーピング (Root-Cause Prioritization)

### 2.1 反例因果グラフの構築
- ソルバが検出した複数の未定義遷移・反例間の因果依存関係を有向非巡回グラフ（DAG）としてモデル化。
- **依存判定ロジック**:
  - ある反例 $A$ の発生条件（前提状態）が、別の反例 $B$ における状態遷移の未定義に起因している場合、$B \to A$ の依存エッジを張る。

### 2.2 根本論点の抽出アルゴリズム
- トポロジカルソートを実行し、入次数（in-degree）が 0 であるノード群（＝先行依存のない根本的な曖昧さ）のみを「最優先論点」として抽出。
- 下流の従属反例群は「根本論点に付随する影響範囲」として折りたたみ、人間の認知負荷を劇的に削減する。

### 2.3 コンポーネント別グルーピング
- 互いに依存のない独立した論点群を、コンポーネントまたはシナリオ単位でグループ化し、人間が 1 つの関心領域に集中して個別の意思決定を進められるようにする。

## 3. 自然言語テンプレートと 3 択生成ロジック

### 3.1 テンプレート構造
1. **主張 (Claim)**: `-- @label` から復元されたドメイン語彙を用い、「本来あるべき前提」を宣言。
2. **観測事実 (Observation)**: 「状態 S において操作 C が未処理である」という客観的事実を記述。
3. **判断質問 (Domain Question: Is this intended?)**:
   - `状態が『${stateName}』のとき、操作『${commandName}』を「非活性（Disabled）」として抑止すべきですか？それとも特定のエラー表示へ遷移させるべきですか？`

### 3.2 意思決定 3 択の自動生成
- **選択肢 A (仕様化)**: 非活性化またはエラー通知処理を形式仕様に正式追加する。
- **選択肢 B (バグ修正)**: モデルまたは実装コードの欠陥として修正する。
- **選択肢 C (例外許容)**: 画面の物理配置上、到達不能なエッジケースとして明示的に許容・無視する。
