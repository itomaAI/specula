# ContextExtractor 仕様書

本仕様書は、機能垂直事実スライスモジュール `ContextExtractor` が果たすべき**責務の境界、取り扱う情報の定義、および守るべき契約（事前・事後・不変条件）**を定義する。
本仕様書はプロダクトマネージャー（PdM）やステークホルダーがシステムの振る舞いとして読解・合意可能な形式で記述され、プログラミング言語固有の内部コードには依存しない。

---

## 1. 責務の境界 (Responsibilities & Scope)

### 1.1 担当すること (In Scope)
- **指定シナリオを起点とする機能垂直事実スライス抽出**:
  - 入力として与えられたシナリオ同定情報 `CommandTarget` の**起点の所在**（起点となる処理が定義されているファイルと、その処理の名前）から追跡を始め、シナリオの達成に直接関与する要素のみをピンポイントで機能垂直抽出する。
  1. **画面・UI層**: シナリオにリードモデル（画面）があるときだけ、その画面の関連UI要素、状態（`STATE`）、および操作ハンドラ（`OPERATION`）を抽出する。画面を持たないシステムでは、この層は無い。
  2. **API・ビジネスロジック層**: 起点の処理と、そこから呼び出される処理（APIエンドポイント、関数）。画面を持たないシステム（ライブラリ、コマンドラインツール）では、起点の公開関数と、そこから呼び出される関数がこの層に当たる。
  3. **非同期バッチ・トリガー層**: その操作に関連して発火・購読されるイベント駆動処理。
  4. **データモデル層**: その操作で読み書きされるデータベースコレクション/テーブルスキーマ。
- **厳密な探索境界規則 (Causality & Consistency Boundaries)**:
  1. **開始境界 (Inlet Boundary)**:
     - 単一の操作ハンドラ（UIイベント等）、単一の外部トリガー（1つのAPIエンドポイント受信点、1つのバッチ起動点等）、または単一の公開関数のみを起点とする。
  2. **終了境界 (Outlet Boundary)**:
     - 呼び出し元へ**結果（応答）が確定・返却された時点**で探索を打ち切る。
       - **更新系 (Command / Mutation)**: 状態変化（DB書き込み等）が確定し、呼び出し元への応答（画面フィードバック、APIレスポンス）が返った時点。
       - **参照系 (Query / Read)**: 副作用（状態変化）を伴わずにデータソース等から事実が読み出され、呼び出し元への応答が返った時点。
       - **ガード失敗・拒絶系 (Early Return)**: バリデーション失敗や権限エラー等により、早期にエラー応答が返った時点。
       - **公開関数**: 起点の関数が値を返した時点、または例外を投げた時点。
  3. **非同期境界 (Asynchronous Boundary)**:
     - 非同期の境目（永続化の確定、メッセージキューへのエンキュー）でスライスを物理的に切断する。
     - キューやDB変更を契機に発火する後続の非同期処理は、そのデータ（テーブル/キュー）を開始境界とする別シナリオとして分離し、同一スライス内に混ぜて追跡しない（両者は共有データモデルのみを介して疎結合に繋ぐ）。
  4. **分岐のスライシング (Branching / Use Case Slice)**:
     - ガード条件・例外・権限・状態違いにより因果経路や結果が分岐する場合、それぞれの分岐パスを独立したユースケーススライスとして識別・抽出する。スライスは**出口（応答・返り値・例外）ごとに 1 つ**とし、その出口に至る条件を持つ。
  5. **追跡できない呼び出し**:
     - 解析対象の外（外部パッケージ）の処理や、コードから呼び出し先を決められない呼び出しは、追跡せずに「追跡できない呼び出し」として所在と理由を記録する。呼び出し先の振る舞いを推測で補わない。
- **シナリオ垂直事実モデル (`RawContextModel`) の出力**:
  - 無関係なファイルや画面全体のノイズを排除し、「指定シナリオを成立させている垂直因果チェーン」のみを純粋に凝縮した事実モデルを出力する。

### 1.2 扱わないこと (Out of Scope / 禁止事項)
- **リポジトリ全体の無差別なAST解析**: シナリオに無関係な全ファイルの走査や解析は行わない（探索範囲の制限）。
- **どのシナリオを抽出するかの決定**: シナリオの同定・切り出し自体の探索や選定は行わない（与えられた入力ターゲットに厳格に従う）。
- **ドメイン意図の推測や正否判断**: 実装に存在する客観的事実のみを抽出し、勝手な意味づけやバグ修正は行わない。LLM は使わない。
- **「バグ」と「仕様」の区別**: 実装の振る舞いは事実として読み取り、バグか仕様かを区別しない。違和感のある振る舞いに注意を向ける機能は、結果をレビューする別のモジュールの責務とする（現時点では作らない。全体仕様書 1.4 を参照）。
- **原本の改変**: ソースコード、画像、スキーマ原本は一切変更しない（完全なRead-only）。

## 2. 取り扱う情報の定義 (Information Model)

### 2.1 入力情報 (Inputs)
| 入力情報 | 内容 | 必須/任意 |
| :--- | :--- | :--- |
| **シナリオ同定情報 (`CommandTarget`)** | 対象シナリオの識別子、起点の種別と所在、リードモデル（ある場合） | 必須 |
| **ソースコード群 (`SourceArtifacts`)** | 垂直探索過程でオンデマンドに読み込まれるソースファイル群（フロント/バック/DB） | 必須 |
| **画面画像 (`VisualArtifact`)** | 対象エントリーポイント画面のスクリーンショット | 任意 |

### 2.2 出力情報 (Outputs)
- **`シナリオ垂直事実モデル (RawContextModel)`**:
  - **対象シナリオ参照**: `commandId` と、起点の種別と所在
  - **垂直抽出ユニット一覧**:
    - 画面UI操作事実（ボタン、入力、画面ラベル、状態変数）
    - 処理の事実（API エンドポイントとパラメータ、呼び出した関数、状態変数とその変更、分岐の条件、返り値と例外）
    - データ変更事実（対象テーブル/コレクション、更新フィールド）
    - 非同期トリガー事実（関連イベント、非同期境界で切断した箇所）
  - **ユースケーススライス一覧**: 出口ごとに、その出口に至る条件（条件の式と、どちらの側を通るか）、出口の種類（応答・返り値・例外・非同期境界）、経路上で変わる状態
  - **追跡できない呼び出しの一覧**: 所在と理由

意図の候補は `IntentSynthesizer` が持つので、`RawContextModel` には写さない。本モジュールは意図の候補を入力にも使わない。

## 3. 契約仕様 (Design by Contract)

### 3.1 事前条件 (Preconditions)
- 有効な `CommandTarget` が提供されており、起点の所在（ファイルと処理の名前）が解析対象の中に存在すること。存在しないときは、推測で別の処理を起点にせず、失敗として理由を返す。

### 3.2 事後条件 (Postconditions)
- 開始境界（操作、トリガー、公開関数）から終了境界（応答返却、返り値、例外）までの因果チェーンが過不足なく追跡され、該当シナリオの完結に必要な事実（更新系における永続化、参照系における取得事実、あるいは拒絶結果）が漏れなく `RawContextModel` に含まれていること。追跡できなかった部分は、追跡できない呼び出しとして記録されていること。
- 非同期境界を越えた後続処理や、シナリオに関与しない無関係な画面・ロジックの事実が含まれていないこと（スライスの局所性・境界遵守）。
- 起点の処理のすべての出口に、ユースケーススライスが 1 つずつあること。

### 3.3 不変条件 (Invariants)
- **非推測・完全事実性**: 実装コードや画像に存在しない架空の要素を混入させないこと。
- **決定論性**: 同一の `CommandTarget` およびソース群から、常に完全に同一の `RawContextModel` を出力すること。
- **非破壊性**: 解析対象のファイルシステムを一切変更しないこと。
