# FormalTranspiler 仕様書

本仕様書は、形式仕様変換モジュール `FormalTranspiler` が果たすべき**責務の境界、取り扱う情報の定義、および守るべき契約（事前・事後・不変条件）**を定義する。
本仕様書はプロダクトマネージャー（PdM）やステークホルダーがシステムの振る舞いとして読解・合意可能な形式で記述され、特定の形式言語（Alloy等）の実装構文には依存しない。

---

## 1. 責務の境界 (Responsibilities & Scope)

### 1.1 担当すること (In Scope)
- **事実モデルから形式仕様コードへの決定論的変換**:
  - ContextExtractor が抽出した事実モデル（状態変数とその変更、分岐の条件、出口）を入力とし、状態・操作・条件からなる形式仕様コードを出力する。
  - 状態は、状態変数の値と、直前の操作がどの出口に至ったかから作る。
  - **実装詳細の隠蔽**: 形式仕様コードの公開識別子には、内部変数名、ライブラリ名、フレームワーク予約語を使わない。公開識別子は機械的に決め、業務ドメインの語（表示名）は別の対応表として付ける。
- **仕様の曖昧性検知と人間への補完要求 (Ambiguity Detection & Human Clarification)**:
  - 状態変数がとりうる値を事実から決められない、外部の呼び出しが状態を変えるか決められない、などの理由で一意な形式仕様へ落とせない場合、**推測による穴埋めをせず、曖昧性レポート（`AmbiguityReport`）を出力して人間（PdM）へ補完を促す**。
  - 曖昧な箇所は最初の 1 件で止めずにすべて集め、種類ごとの件数を出す。

### 1.2 扱わないこと (Out of Scope / 禁止事項)
- **数学的検証の実行**: 全状態空間探索やモデル検査、反例の探索は行わない（形式仕様の構築に閉じる）。検査のコマンドは FormalSolver が組み立てる。
- **人間向けドキュメント（Markdownや図式）の射影**: 自然言語文書やグラフなどの可視化ビューの生成は行わない。
- **推測による曖昧性の勝手な解決**: 曖昧な事実をプログラミング的推測で自己修復・捏造することは固く禁ずる。
- **業務ルールの推測**: 初回の実行では、業務上の不変条件や守るべき性質をコードから推測して書かない。これらは人が論点に判断を下した後（2 回目以降）に足す。
- **前版との差分（現在の範囲外）**: 前版の正本との比較は 2 回目以降の処理であり、現在は行わない。

## 2. 取り扱う情報の定義 (Information Model)

### 2.1 入力情報 (Inputs)
| 入力情報 | 内容 | 必須/任意 |
| :--- | :--- | :--- |
| **システム客観事実モデル (`RawContextModel`)** | ContextExtractor が抽出した、状態変数・状態の変更・分岐の条件・出口と、出口ごとのスライス | 必須 |
| **前版 形式仕様正本 (`PreviousFormalSpec`)** | 過去のイテレーションで合意・コミットされた形式仕様コード | 任意（初回は null。現在は差分を作らない） |

### 2.2 出力情報 (Outputs)
以下のいずれかを出力する：

1. **`形式仕様コード (FormalSpecification)`** 【変換成功時】:
   - **状態空間**: 状態変数とそのとりうる値、初期値（事実から決まるものだけ）、直前の操作の結果
   - **操作**: スライスごとの状態遷移（条件、状態の変更、至る出口）
   - **環境が決める条件**: 状態変数で表せない条件（関数の戻り値や引数の値など）。どの組み合わせも起こりうるものとして扱う
   - **出どころの対応表**: 形式仕様の各要素と、元の実装の箇所との対応
   - **表示名**: 各要素の業務ドメインの語。LLM に届かなかったときは「未生成」
   - **前版との差分**: 現在は「作っていない」と記録する
2. **`仕様曖昧性レポート (AmbiguityReport)`** 【曖昧性検知時】:
   - 形式化を阻害している箇所の一覧（種類、実装の箇所、式や呼び出しの原文）
   - 人間（PdM）が補完・明確化すべき質問の文（LLM に届かなかったときは「未生成」）
   - 種類ごとの件数

## 3. 契約仕様 (Design by Contract)

### 3.1 事前条件 (Preconditions)
- 入力される `RawContextModel` が少なくとも 1 つのスライスを含み、スライスが参照するユニットがすべて存在すること。満たさない場合は ContextExtractor の契約違反として例外にする（曖昧性レポートにはしない）。

### 3.2 事後条件 (Postconditions)
- **分岐 A (成功時)**: 状態を事実から決められた場合、ソルバでコンパイル可能な形式仕様コードが出力されること。
- **分岐 B (曖昧性検知時)**: 状態を事実から決められない箇所が 1 つでもある場合、形式仕様コードは出力せず、`AmbiguityReport` が出力されて人間へ判断が委ねられること。

### 3.3 不変条件 (Invariants)
- **完全隠蔽性**: 内部の変数名や実装固有のキーワードが、形式仕様の公開識別子として漏洩しないこと。公開識別子は機械的に決める。出どころ注釈（`@source` など）に元の識別子を書くことは許され、これは公開識別子に含まれない（射影ビューと論点カタログを作るときに取り除かれる）。
- **トレーサビリティの保持**: 形式仕様の各要素には、原本コードとの対応関係を逆引き検証できるよう、出どころの証跡を保持すること。
- **決定論性**: 同一の入力に対して、いつ何度実行しても、形式仕様コードと曖昧性レポートの構成（種類・箇所・件数）は完全に同一であること。形式仕様コードは LLM の結果によらない。LLM が作る表示名と質問の文は、記録して再利用することでこれを満たす。
