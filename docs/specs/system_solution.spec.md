# 汎用仕様抽出・検証システム 全体仕様書 (System Solution Specification)

本仕様書は、汎用仕様抽出・検証システム（Universal Spec Extraction & Verification Platform）が外部に対して提供する**ブラックボックスとしての振る舞い、大域情報モデル、および守るべき契約（事前条件・事後条件・不変条件）**を定義する。
本システムをどう実装するか（内部アルゴリズム、使用ライブラリ、具体的なパーサー等）には一切言及しない。

---

## 1. システム理念と Loom 双対モデル

### 1.1 背景と目的
ソフトウェア開発において、コードは Git で、デザインは Figma で管理されるが、「仕様」は属人化し散逸している。本システムは、既存の実装（コードおよび画面）からドメイン仕様を客観的に奪還し、数学的に検証された仕様を「唯一の正本（Single Source of Truth）」として維持・編集・射影するプラットフォームを提供する。

### 1.2 Loom 双対構造（プロジェクト／タスク）の大域適用
本システムが取り扱う知識および処理の単位は、すべて Loom の 2 大概念に準拠してモデル化される：

1. **プロジェクト相当 (Bounded Context / System Root)**:
   - **性質**: 終わらない観点、意図（Why）、および文脈（Context）を持つ大域的な器。
   - **保持情報**:
     - `## 意図`: システムおよび各ドメイン境界の存在理由・責務。
     - `## 文脈`: ドメインイベントの連鎖（Event Storming 全体マップ）、外部との境界。
2. **タスク相当 (Individual Scenario)**:
   - **性質**: 単一の明確な完了条件を持つ、1本のアトミックな仕事（状態遷移・因果スライス）。
   - **保持情報**:
     - `## 依頼`: 単一の起点（Command または Policy）と実行主体（Actor）。
     - `## 前提・リードモデル`: 操作の起点となる画面・情報ビュー（Read Model）。
     - `完了条件`: 確定すべきドメインイベント（Expected Domain Event）。

### 1.3 3つの基本操作（置く・畳む・移す）によるライフサイクル
- **置く（分解 / Decompose）**: システム全体から Bounded Context（プロジェクト）を同定し、その内部から個別シナリオ（タスク）をアトミックに切り出す。
- **畳む（集約 / Fold）**: 検証・合意された個別シナリオの論点・不変条件を集約し、親コンテキストの文脈（仕様正本・ナレッジ）へと還元する。
- **移す（伝播 / Transfer）**: あるコンテキストで確定したドメインイベントを、別コンテキストのポリシー起動トリガーへと越境伝播させる。

### 1.4 事実の読み取りと評価の分離
- 本システムは、実装（コードおよび画面）に存在する振る舞いを**事実として**読み取る。読み取りの段階では「バグ」と「仕様」を区別しない。
- 反例が出ない（形式仕様としては整合している）が意図とは異なる振る舞いに注意を向ける機能は、抽出・検証の結果をレビューする**別のモジュール**の責務とする。このモジュールは現時点では作らない。
- 意思決定論点カタログの選択肢にある「バグとして修正する」は、人間が選ぶ判断であり、システムが事実を読み取る段階での区別ではない。

## 2. 外部公開インターフェース仕様 (Public Interface)

本システムは、モジュール自律性を前提とした以下の決定論的システムコマンド群を提供する：

### 2.1 システムコマンド一覧
1. **`DiscoverSystemContext(repo: RepositoryArtifacts) -> EventStormingMap`**
   - リポジトリ構造から Bounded Context を同定し、ドメインイベント・コマンド・ポリシー・リードモデルを束ねた全体マップを出力する（プロジェクトの構築）。
2. **`SliceScenarios(map: EventStormingMap, filter?: ScenarioFilter) -> ScenarioTarget[]`**
   - 全体マップから、コマンドまたはポリシーを起点とする個別シナリオ群をアトミックに切り出す（タスクの分解・配置）。
3. **`ExtractContext(target: ScenarioTarget, sources: SourceArtifacts) -> RawContextModel`**
   - 単一の個別シナリオを起点とし、開始境界（Inlet）から終了境界（Outlet）までの因果チェーンのみを非同期境界を跨がずにピンポイントで垂直抽出する。
4. **`TranspileFormal(facts: RawContextModel, previous?: FormalSpec) -> FormalSpec | AmbiguityReport`**
   - 実装固有の変数や構文を完全に隠蔽し、ドメイン概念・状態・操作・制約からなる形式仕様正本へと決定論的にコンパイルする。曖昧性が存在する場合は自己補完せず曖昧性レポートを出力する。
5. **`VerifySpecification(spec: FormalSpec, options?: SolverOptions) -> SolverReport`**
   - 形式仕様正本に対し、決定論的数学ソルバを用いて全状態空間探索を行い、未定義遷移・デッドロック・不変条件違反の反例トレースを網羅検出する。
6. **`SynthesizeLedger(report: SolverReport, spec: FormalSpec) -> DomainLedgerCatalog`**
   - 数学的反例データを、ステークホルダーが判断可能な「意思決定の問い」と選択肢へと逆翻訳し、根本論点を優先抽出する。
7. **`ProjectSpecification(spec: FormalSpec, ledger?: DomainLedgerCatalog, req: ProjectionRequest) -> SpecificationViews`**
   - 形式仕様正本および合意された論点から、Markdown仕様書、因果DAGグラフ、シーケンス図、マトリクス等を決定論的にオンデマンド射影する。

## 3. 大域的契約仕様 (Global Design by Contract)

### 3.1 事前条件 (Preconditions)
1. 入力リポジトリ情報に、解析可能なコードまたはメタ情報（README、ルート定義、スキーマ等）が存在すること。
2. 個別シナリオの抽出に際しては、有効な開始エントリーポイントが特定されていること。

### 3.2 事後条件 (Postconditions)
1. **境界遵守**: 抽出される事実およびモデルは、指定されたシナリオの境界（InletからOutletまで）に閉じ、非同期境界を越えた無関係な処理を含まないこと。
2. **形式完全性**: 導出された形式仕様は数学的にコンパイル可能であり、**指定スコープ内の**検証空間におけるすべての不変条件違反が、元の記録（検証結果レポート）に余すことなく残ること。
   - 検証結果レポートは元の記録として、全件と、結果を再現するための実行条件（エンジンの版、SAT ソルバ、スコープ、分割の仕方）を保持する。
   - 意思決定論点カタログは元の記録の要約であり、全件を並べなくてよい。その代わり、どのレポートの反例 N 件を論点 k 件にまとめたか、従属として後ろに回した反例がどれかを必ず示す。これにより「すべての違反が、元の記録か、そこからたどれる論点のどちらかに載っている」ことを保つ。
3. **人間中心の意思決定**: 仕様の曖昧さや反例の解決をシステム自身が推測で行わず、必ず人間への意思決定論点として提示されていること。
4. **射影整合性**: 射影されたすべてのビュー（Markdown、グラフ等）が、形式仕様正本と 100% 整合していること。

### 3.3 不変条件 (Invariants)
1. **完全隠蔽性**: 最終仕様書、形式仕様正本、および論点カタログには、内部実装固有のフレームワーク予約語や内部変数が一切漏洩しないこと。
2. **完全決定論性**: 同一の入力から導出される仕様モデル、反例、および射影ビューは、いつ何度実行しても完全一致（差分ゼロ）すること。
3. **フォールバック保証**: Bounded Context の境界が曖昧な場合でも処理を停止させず、単一コンテキストとして一貫性を維持してモデル化すること。
4. **非破壊性**: 入力されたソースコード、画面画像、ドキュメント原本を一切改変しないこと。
