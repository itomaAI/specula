# SpecProjector 仕様書

本仕様書は、仕様射影モジュール `SpecProjector` が果たすべき**責務の境界、取り扱う情報の定義、および守るべき契約（事前・事後・不変条件）**を定義する。
本仕様書はプロダクトマネージャー（PdM）やステークホルダーがシステムの振る舞いとして読解・合意可能な形式で記述され、プログラミング言語固有の内部コードには依存しない。

---

## 1. 責務の境界 (Responsibilities & Scope)

### 1.1 担当すること (In Scope)
- **形式仕様正本からの多面的・マルチ粒度ビューの決定論的射影**:
  - 正本である形式仕様コード（`FormalSpec`）および合意された `DomainLedgerCatalog` を入力とし、**利用者が指定した表現形式や粒度に応じた仕様ビュー（Specification Views）を決定論的にオンデマンド射影**する。
  - **出力形式ごとのプラグイン射影**:
    1. **ドキュメント表現 (Document Projection)**: Markdown形式によるブラックボックス仕様書（`spec.md`）。
    2. **グラフ表現 (Graph / DAG Projection)**: 因果関係・依存関係を視覚化する DAG データ（`dag.json`、Mermaid グラフ）。
    3. **フロー・時系列表現 (Flow / Sequence Projection)**: ユーザーとシステムの対話系列を表すフローチャートおよびシーケンス図。
    4. **マトリクス表現 (Matrix Projection)**: 状態×操作の網羅関係を表す状態遷移決定表。
- **抽象度（ズームレベル）に応じた粒度調整**:
  - サービス全体の俯瞰マクロビューから、単一シナリオ・単一オペレーションのミクロ詳細ビューまで、利用者の要求粒度に応じた射影を提供する。

### 1.2 扱わないこと (Out of Scope / 禁止事項)
- **テストコードへの変換**: 仕様からテストコード（`test.ts`）を生成する処理は別ツールの責務であり、本モジュールでは取り扱わない（仕様の世界に閉じる）。
- **生成ビューの正本化**: 射影された Markdown やグラフを正本として永続管理してはならない（正本は常に形式仕様コードのみ）。
- **非決定論的な出力**: 同一の正本・同一の出力要求に対し、レイアウトやテキストの表現が揺らぐことを固く禁ずる。

## 2. 取り扱う情報の定義 (Information Model)

### 2.1 入力情報 (Inputs)
| 入力情報 | 内容 | 必須/任意 |
| :--- | :--- | :--- |
| **形式仕様正本 (`FormalSpec`)** | 唯一の正本である形式仕様コード | 必須 |
| **意思決定論点カタログ (`DomainLedgerCatalog`)** | 人間が判断・合意した論点結果データ | 任意 |
| **射影リクエスト (`ProjectionRequest`)** | 要求する表現形式（Markdown / DAG / Flow / Matrix）およびズーム粒度 | 必須 |

### 2.2 出力情報 (Outputs)
- **`仕様ビュー成果物 (SpecificationView)`**:
  - リクエストされた形式に応じた決定論的データ（Markdownテキスト、Mermaid定義文字列、またはグラフ構造JSON）。

---

## 3. 契約仕様 (Design by Contract)

### 3.1 事前条件 (Preconditions)
- 入力される `FormalSpec` が構文エラーなくパース可能であること。
- 指定された表現形式および粒度が、サポートされている射影サブモジュールの定義に合致していること。

### 3.2 事後条件 (Postconditions)
- 正本に含まれるすべてのドメイン概念、事前・事後・不変条件、オペレーションが、指定された表現形式のセマンティクスに忠実に射影されていること。

### 3.3 不変条件 (Invariants)
- **完全決定論的再現性 (100% Determinism)**: 同一の形式仕様正本と同一の射影リクエストが与えられた場合、いつ何度再生成しても出力結果は完全一致（`git diff = 0`）すること。
- **純粋射影（非破壊性）**: 射影処理によって正本の内容を一切改変しないこと。
