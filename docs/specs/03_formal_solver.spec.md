# FormalSolver 仕様書

本仕様書は、形式仕様検証モジュール `FormalSolver` が果たすべき**責務の境界、取り扱う情報の定義、および守るべき契約（事前・事後・不変条件）**を定義する。
本仕様書はプロダクトマネージャー（PdM）やステークホルダーがシステムの振る舞いとして読解・合意可能な形式で記述され、プログラミング言語固有の内部コードには依存しない。

---

## 1. 責務の境界 (Responsibilities & Scope)

### 1.1 担当すること (In Scope)
- **「LLM単体に論理計算をさせない」決定論的数学検証**:
  - 形式仕様コードを入力とし、指定スコープ内の全状態空間 $S \times C$（状態×操作）を決定論的に探索・検証する。
  - **未定義遷移の検出**: ある状態で特定の操作が実行された際に、事後状態が定義されていないパターン（死角・抜け漏れ）を網羅検出する。
  - **デッドロックの検出**: 終端状態でないにもかかわらず、次の操作で脱出できない孤立状態を検出する。
  - **不変条件違反の最小反例トレース抽出**: 表明された安全制約を破る最短の実行操作系列を導出する。
- **分割統治による自律的自己解決 (Compositional Slicing & Autonomous Partitioning)**:
  - 状態空間が膨大で一度に全探索が完了できない場合（タイムアウトや計算限界の予兆検知時）、**人間を煩わせることなく、シナリオ単位・操作単位に状態空間を自動分割（スライシング）して段階的・並行的に再実行し、網羅的検証を自律完遂**する。

### 1.2 扱わないこと (Out of Scope / 禁止事項)
- **反例データの自然言語への翻訳**: 機械的トレースの自然言語化や人間向け質問文の作成は行わない（検証結果の計算に閉じる）。
- **推測による仕様の自動修正**: 検出された未定義や矛盾を勝手に補完・解決しない。
- **非決定論的な探索**: 試行環境や実行タイミングによって結果が揺らぐ確率的探索を行わない。

## 2. 取り扱う情報の定義 (Information Model)

### 2.1 入力情報 (Inputs)
| 入力情報 | 内容 | 必須/任意 |
| :--- | :--- | :--- |
| **形式仕様正本 (`FormalSpec`)** | 検証対象となる形式仕様コード | 必須 |
| **探索オプション (`SolverOptions`)** | 探索スコープ（検証対象インスタンス数の上限、時相ステップ数） | 任意（既定値あり） |

### 2.2 出力情報 (Outputs)
- **`検証結果レポート (SolverReport)`**:
  - **完全性・健全性フラグ**: モデルに矛盾や未定義が存在しないか否か
  - **分割実行メタデータ**: 状態爆発時に自律分割（スライシング）されて再実行された経緯と分割単位
  - **未定義遷移一覧**: ハンドリングが欠落している `[状態, 操作]` の組み合わせリスト
  - **デッドロック一覧**: 復帰不能・脱出不能な状態のリスト
  - **最小反例トレース一覧**: 各検証アサーションを破る具体的な状態遷移系列（ステップごとの状態値）

---

## 3. 契約仕様 (Design by Contract)

### 3.1 事前条件 (Preconditions)
- 入力される形式仕様コードが構文的に妥当であり、有限状態機械（FSM）として定義されていること。

### 3.2 事後条件 (Postconditions)
- スコープ内に存在するすべての未定義遷移、デッドロック、および不変条件違反が余すことなく抽出され、レポートに含まれていること。

### 3.3 不変条件 (Invariants)
- **完全決定論性**: 同一の仕様コードを入力とした場合、実行環境に関わらず、常に完全に同一の反例パスおよび探索結果を返すこと。
- **完全性保証**: 反例が存在する場合、必ず最短ステップの実行トレースを報告すること。
